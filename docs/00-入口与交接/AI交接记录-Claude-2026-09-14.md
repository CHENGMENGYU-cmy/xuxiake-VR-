## 三、文档未记录 / 与实际不符的偏差

### 偏差 1（重要）· 图片"显示不出来"很可能是误报，不要重复排查

用户反馈"有图片的数据没办法好好显示出来"。我做了零到一的排查，**结论是图片显示正常：滚到底部后 25/25 张图片全部加载成功，全站没有任何 HTTP ≥400 请求**。

误报来自两个陷阱（下一个模型请直接避开，别再花时间）：

1. **滚动容器不是 `window`，而是 `<main class="flex-1 overflow-y-auto">`**。
   `window.scrollTo()` 完全无效（`document.body.scrollHeight` 恒等于视口高）。必须驱动 `main.scrollTop` 或对 `main` 元素滚动。
2. **帖子图片是 `loading="lazy"`**。未滚到视口内时 `naturalWidth === 0`，脚本会误判为"破图"。

**正确验证方法**（可直接复制）：

```js
await page.evaluate(async () => {
  const main = document.querySelector('main');
  for (let y = 0; y <= main.scrollHeight; y += 500) {
    main.scrollTop = y;
    await new Promise(r => setTimeout(r, 400));
  }
});
// 之后再统计 img.complete && img.naturalWidth > 0
```

codex 在 `AI_HANDOFF.md` 第 97 行也提过这个懒加载陷阱，但没给出原因（滚动容器），导致容易再次踩坑。

### 偏差 2（真实缺陷）· 6 条视频素材全部指向不存在的文件

- `media_items` 中 6 条 `VIDEO` 的 `url` 全是 `/uploads/demo-videos/preview-unavailable.mp4`
- **`server/uploads/demo-videos/` 这个目录根本不存在**（已确认 `Test-Path = False`）
- 前端降级为「封面 + "视频演示素材，当前仅展示封面，真实上传后可播放视频"」

这是**用户能直接看到的"有媒体的帖子显示不出来"**——很可能正是用户抱怨的那个现象。
